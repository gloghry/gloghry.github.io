# Repository instructions

## Issue-based workflow

- Every repository change must be associated with a GitHub issue, including documentation, configuration, copy, maintenance, and agent-rule changes.
- Before editing, find an existing issue that covers the work or create one. Do not create duplicate issues for follow-up fixes within the same scope.
- Start from the latest default branch and create or switch to a dedicated issue branch before making changes. Prefer `<issue-number>-<short-description>`.
- Keep unrelated work in separate branches and pull requests. Preserve uncommitted work belonging to other tasks.
- Reference the issue in the pull request. Use `Closes #N` only when the change completes its scope; otherwise use `Related to #N` and state what remains.
- Check review feedback and CI before reporting a change as ready. Report any verification that could not run.

## Pull request attribution

- Every PR created or substantially implemented by Codex must clearly disclose that assistance in its description.
- Start the footer with: **AI assistance:** Implemented with OpenAI Codex; opened through Garett’s connected GitHub account. Adapt the contribution wording when appropriate.
- Include a concise metadata table listing the Codex client/surface, its version when verifiable, exact model ID(s) or snapshots used when exposed, and verified additional agent/model involvement.
- Label a locally installed CLI version as an installed CLI version unless it is confirmed as the active client. Do not equate a local binary version with a hosting-app or backend version.
- Distinguish configured/requested model names from verified runtime model IDs. If the exact model, client version, or snapshot is not exposed, write `Not exposed to this session`; do not infer it from product names, defaults, available-model lists, or documentation.
- Record additional models only when their actual involvement is verified. Keep external Copilot review separate from implementation; do not guess its model.
- Describe metadata as observed during the work, not a complete historical record. Do not retroactively claim the current version/model was used for earlier commits without evidence.
- Preserve credit for Garett's supplied writing, palette, design choices, and other inputs. Do not describe human-authored material as generated by Codex.
- GitHub's author field remains the authenticated account. The disclosure is attribution, not a separate bot identity or a change to account ownership.
- Include the disclosure when opening the PR and retain/update it accurately when editing the description.

## Copy and content

- Use Garett's supplied and approved drafts as the baseline. Make focused edits instead of replacing his voice with generic portfolio or résumé language.
- Keep current work, technical experience, leadership experience, and education status accurate. Ask about missing personal details rather than inventing them.
- Do not publish private workplace incidents or infer permission to publish contact details from source material.

## Development

See [CONTRIBUTING.md](CONTRIBUTING.md) for setup, checks, publication, and content authoring. Run checks appropriate to the change; do not add tests merely to mirror prose edits.
